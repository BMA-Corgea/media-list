# T-2 — Skeleton: FastAPI on 7799, self-creating SQLite, and the skin contract

**Type** feature · **Risk** medium · **Intent** T-1 · **After** — (foundation)

## Why this ticket exists

Every other ticket on the branch sits on this one. It delivers three things that are
worthless apart and a real deliverable together: a process that boots, a database that
exists, and a token layer that makes the rest of the app look like something. A skin with
no page is nothing; an empty DB with no app is nothing.

## Context and citations

- Port `7799` is reserved for this project in `../PROJECT_PORTS.md` (amended 2026-09-04),
  loopback-only on purpose — it serves a private list.
- The skin contract is ported from `../repo-tour/src/skins.ts` and
  `../repo-tour/assets/skins/base.css`, which took it from GLP-Strong-App's `public/skins/`
  + `src/theme/themes.ts`. It has survived one move already.
- Privacy boundary is set in `.gitignore` and documented in `README.md`: `data/` never
  enters git because the DB and cached artwork reveal the list.
- `kind` includes `game` as of the 2026-09-04 amendment in `kb/CURRENT-WORK.md`.

## Scope

**In:** backend process + config, `start.sh`, SQLite bootstrap and schema, Vite frontend
built and served by the backend, the skin system with base + two alternates and a working
switcher, a health endpoint.

**Out:** any TMDB/IGDB/AniList call (T-3), any way to add a title (T-4), the carousel
(T-5), and every other surface. This ticket ships an app that boots and looks right with
no data in it.

## Acceptance criteria — all testable

1. **AC1 — it boots.** `./start.sh` starts uvicorn on `127.0.0.1:7799`. `GET /api/health`
   returns `200` with the app version and the resolved DB path. Host and port are
   overridable via `MEDIA_LIST_HOST` / `MEDIA_LIST_PORT`.
2. **AC2 — the database creates itself.** With `data/` deleted entirely, starting the app
   recreates `data/media-list.db` with the full schema and no error. **Deleting `data/` and
   rebooting is the acceptance test.**
3. **AC3 — bootstrap is idempotent.** A second start against an existing DB changes nothing
   and loses no rows. Verified by inserting a row, restarting, and reading it back.
4. **AC4 — the schema is complete for the branch.** `titles` carries: `id`, `source`
   (`tmdb`|`igdb`), `source_id`, `imdb_id` (**nullable** — games have none), `anilist_id`
   (nullable), `title`, `original_title`, `year`, `kind` (`anime`|`movie`|`live-action`|
   `game`), `summary`, `poster_path`, `backdrop_path`, `genres`, `detail` (JSON, per-kind
   extras), `why`, `status` (`queued`|`seen`), `stars` (nullable 1–5), `review`,
   `queue_position`, `added_at`, `watched_at`. Unique index on `(source, source_id)`.
5. **AC5 — the frontend is served by the backend.** A production Vite build is served at
   `/`; unknown non-`/api` paths fall through to `index.html` so client routing works.
   `5799` runs the Vite dev server against the same API.
6. **AC6 — the skin contract holds.** `base.css` owns bare `:root` and carries the design
   tokens **and** the component layer. Each alternate is one file whose every rule is
   scoped under `:root[data-theme="<name>"]`. Adding a skin costs exactly one CSS file plus
   one registry row — no other file changes. At least two alternates ship.
7. **AC7 — switching works and persists.** Choosing a skin restyles every surface with no
   reload, survives a refresh, and applies **before first paint** (no flash of the previous
   skin). Verified by setting a skin, hard-refreshing, and observing no flash.
8. **AC8 — nothing private is committable.** `git status --porcelain` is clean of `data/`,
   `*.db` and `.env` after a full boot that has written the database.

## Constraints

- FastAPI + uvicorn, Vite frontend, SQLite via the stdlib `sqlite3` — no ORM, no migration
  framework, no container. Evan: *"It's not a big project."*
- `start.sh` must **not** free the port first. It serves private data; it refuses to fight
  over a socket rather than killing whatever holds it (repo-tour's stance, recorded in
  `../PROJECT_PORTS.md`).
- No hardcoded colours anywhere outside `base.css` and the skin files.

## Evidence the build must produce

The delete-`data/`-and-reboot run, the insert/restart/read-back run, a `git status` after
boot, and a note of which two alternates shipped.
