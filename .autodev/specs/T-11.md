# T-11 — Pexels chrome pass: ambient imagery and credits

**Type** feature · **Risk** low · **Intent** T-1 · **After** T-5

Uses Evan's Pexels key to dress the surfaces the other tickets built. **Ambient imagery only
— Pexels is never a source of title artwork.** Stock photography cannot supply key art, and a
poster wall made of it is the spreadsheet problem in costume.

## Acceptance criteria

1. **AC1 — fetched once, then local.** A script pulls the images and saves them into the
   frontend's committed tree. **No surface makes a network call at runtime.**
2. **AC2 — every image is credited.** `credits.json` beside them with creator, licence,
   source URL, photographer URL, alt text, and *why that image was chosen* — the
   GLP-Strong-App pattern.
3. **AC3 — these images ARE committed** (generic, and a fresh clone should look right),
   unlike title art which stays in gitignored `data/`.
4. **AC4 — it works under every skin.** Images sit behind token-driven scrims, never
   dictating colour. Verified in `system`, `nocturne` and `paperback`.
5. **AC5 — dressed surfaces:** the empty state, the Seen archive header, and the ground
   behind the carousel.
6. **AC6 — no regression in the colour-literal rule.** The grep checks T-5, T-7, T-8 and T-9
   established still pass — this ticket must not sneak a hue into those blocks.
7. **AC7 — T-2's traversal regression re-run.** This ticket touches the static tree, which is
   exactly the condition T-2 recorded for re-testing.
8. **AC8 — degrades without the key.** With `PEXELS_API_KEY` absent the app still renders;
   the fetch script says what is missing rather than failing silently.
