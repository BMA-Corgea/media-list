# T-3 — Metadata spine: TMDB, AniList, IGDB, and the artwork cache

**Type** feature · **Risk** medium · **Intent** T-1 · **After** T-2

Carries the video-games amendment (Evan, 2026-09-04, `kb/CURRENT-WORK.md`): `kind` is
`anime` · `movie` · `live-action` · `game`, and games come from **IGDB**.

## Why

T-4's promise — type a few words, click a poster, everything fills itself in — is only as
good as what stands behind it. This ticket is that. It is also where the app's one hard rule
is enforced: **the user never types metadata.**

## Acceptance criteria

1. **AC1 — merged search.** `GET /api/search?q=` returns candidates from TMDB *and* IGDB in
   one ranked list. Each carries `source`, `source_id`, `title`, `year`, `kind`, `summary`,
   `poster_url`, `backdrop_url`.
2. **AC2 — kind inference is right.** TMDB result with genre 16 **and** (`origin_country`
   contains `JP` or `original_language == "ja"`) → `anime`; other `tv` → `live-action`;
   `movie` → `movie`; anything from IGDB → `game`. Proven against named titles, not asserted.
3. **AC3 — the disambiguation case works.** Searching `cowboy bebop` returns the 1998 anime,
   the 2021 live-action series and the 2001 film as **three distinct candidates with three
   distinct posters and three distinct source ids**. This is the ticket's headline test.
4. **AC4 — details enrich per kind.** `GET /api/details/{source}/{source_id}` returns
   `imdb_id` for TMDB titles (from `external_ids` — IMDb has no free API, this is the only
   source), AniList extras for anime (studio, episodes, season, romaji + English titles),
   and IGDB extras for games (platforms, developer, genres, IGDB slug for the link).
5. **AC5 — games have no IMDb and that is fine.** A game's `imdb_id` is `null` and its
   outbound link is its IGDB page. Nothing in the response is a dead link.
6. **AC6 — artwork is cached locally, content-addressed.** Images are downloaded into
   `data/art/` and served from `/art/…`; the response never hands the frontend a remote URL.
   Re-fetching the same image is a no-op (byte-identical file, no second download).
7. **AC7 — missing credentials degrade, never crash.** With `IGDB_CLIENT_ID`/`SECRET`
   absent, `/api/search` still returns TMDB results and reports the disabled source rather
   than 500ing. With `TMDB_API_KEY` absent it does the same in reverse.
8. **AC8 — the IGDB token is fetched once and reused.** Twitch `client_credentials` is
   exchanged for a bearer, cached under gitignored `data/`, reused across requests, and
   refreshed only on 401 or expiry. Proven by counting token requests across several
   searches.
9. **AC9 — upstream failure is honest.** A rate limit, timeout or bad key produces a real
   error naming the source, not a silent empty result set that reads as "no matches".

## Out of scope

Storing anything (T-4 owns writes). Any UI. The Pexels chrome pass (T-11).

## Constraints

- `httpx` with explicit timeouts. No SDKs — three small clients are less code than three
  dependencies, and IGDB's SDK does not exist for Python anyway.
- Cached art is **never** written into the frontend's public tree: `data/` is gitignored
  because the artwork reveals the list.
